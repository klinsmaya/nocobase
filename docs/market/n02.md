# N02 目录、发布者、草稿和主体映射

本文记录方案 1.3 的 N02。基线仍是 N01 的 `6c0b83d790234c318dc2d1f2243dcc6e093095d5`，版本线 `2.1.37`。实现在 `@nocobase/plugin-market-catalog`。

## 租户

N01 写明 `@nocobase/plugin-multi-app-manager` 已废弃，不在 `builtIn` 里，不能当作租户隔离。企业授权覆盖仍是 UNKNOWN。本插件不依赖商业插件。

每张业务表有 `ncTenantId`。调用者的租户来自 `marketPrincipals`，按 `ctx.auth.user.id` 查询。请求体里的 `ncTenantId` 会被丢掉，再写成这条主体记录上的租户。资源中间件在 ACL 之前执行，位置与 `@nocobase/plugin-api-keys` 相同：`after: 'auth'`，`before: 'acl'`。

第一个主体不能由未绑定的调用者自己创建，否则调用者可以挑选租户。测试和安装操作通过 `marketPrincipals` 仓库写入第一条记录。已绑定的调用者可以用 `marketPrincipals:create` 在自己的租户里绑定其他用户。一个 `userId` 只有一条主体记录。

列表、读取、更新都带上 `ncTenantId` 过滤。跨租户读取得到空结果，不返回对方的摘要。跨租户的映射修订返回 404。

ACL 片段是 `pm.market-catalog`。`admin` 角色在本提交带有 `pm.*`。片段只决定谁能进入这些动作。租户过滤不靠角色配置是否记得加上。

## 表

| 集合 | 作用 |
| --- | --- |
| `marketPublishers` | 租户内唯一的 `publisherSlug`，所有者是创建时的认证用户 |
| `marketResources` | `resourceId` 为 `publisherSlug/name`。唯一键是租户、发布者、名称、`sourceKey` |
| `marketDrafts` | 每个资源行一份草稿。`revision` 从 1 开始，`etag` 是修订号的十进制字符串 |
| `marketIdentityMappings` | I01 映射。`marketProtocolVersion` 和 `schemaVersion` 固定为 `draft-1` |
| `marketOwnershipEvents` | 只追加的所有权转移记录 |
| `marketPrincipals` | 用户到 `ncTenantId` / `ncSubjectId` 的绑定 |

没有 release、扫描、审核、来源适配器、计划或安装投影。那些仍属于 N03 及以后。

## 草稿 CAS

`marketDrafts:update` 替换了默认更新。请求必须带 `If-Match`，或在 body 里带 `expectedRevision`。两者都给时必须相同。缺少条件返回 428，不写行。修订号不一致返回 409，不写行。

写入是一条带 `id`、`revision` 和 `ncTenantId` 的条件更新。影响行数不是 1 时返回 409。成功后修订号加 1，`etag` 改成新修订号。

## 同名来源

同名不合并。`alpha/research-agent` 和 `beta/research-agent` 是两行。同一发布者下 `sourceKey` 为 `local` 和 `import` 也是两行，`resourceId` 都显示 `alpha/research-agent`。协议里的 `resourceId` 没有来源段，所以来源留在 `sourceKey`，不写进 `resourceId`。

更新不能改 `name`、`sourceKey`、`publisherId` 或 `resourceId`。改这些字段不会变成另一条资源，也不会转移所有权。

## 身份映射

创建时 `revision` 固定为 1，`invalidated` 固定为 false。客户端传来的修订号和失效标记无效。`ncSubjectId` 必须已经是本租户的主体。邮箱字段或 `linkMethod=email` 返回 400。没有按邮箱查找用户的路径。

`marketIdentityMappings:revise` 在同一事务里把当前行标成 `invalidated=true`，并插入下一修订。条件是当前行的修订号，以及 `invalidated=false`。旧修订仍可列出。用旧修订再修订返回 409，不会多出一行。

## 操作者

操作者只来自认证上下文。`ownerUserId` 和所有权事件的 `actorUserId` 使用 `state.currentUser.id`。请求里的 `actor`、`actorUserId`、`ownerUserId` 在中间件被删除。

所有权转移是 `marketPublishers:transferOwnership`。当前所有者才能调用。目标用户必须是同一租户的主体。改显示名不会改 `publisherSlug`，也不会改所有者。转移成功才写 `marketOwnershipEvents`。

未绑定主体的用户调用这些资源返回 403。

## 后台页面

页面走 v1 的 `pluginSettingsManager`，和本提交里 `api-keys`、`auth` 的设置页同一入口。设置项是发布者、资源、草稿、身份映射、主体和所有权事件。草稿保存把当前 `revision` 作为 `expectedRevision` 提交。映射修订同样提交当前修订号。

本提交没有把插件放进预设 `builtIn`，`defaultEnabled` 也没有打开。启用后才会出现这些页面。

## 不在这次里的东西

- `/market/v1` 路由。N02 使用集合资源动作。
- N03 的扫描、审核、不可变 release 和撤销。`verificationStatus` 保持 `unverified`，客户端不能改。
- N04 的来源适配器。`sourceKey` 只是身份的一部分，不会去拉取外部目录。
- 计划、批准、消费方安装。
- `@nocobase/plugin-audit-logs`、`@nocobase/plugin-workflow-approval`、`@nocobase/plugin-multi-app-manager`。
- 用同邮箱或客户端传入的 actor 建立映射。
