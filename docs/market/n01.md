## 哪些插件会随预设装入

`PresetNocoBase.getBuiltInPlugins` 调用 `findBuiltInPlugins`。`findBuiltInPlugins` 读取 `@nocobase/preset-nocobase` 的 `builtIn`，再拼接环境变量 `APPEND_PRESET_BUILT_IN_PLUGINS`。代码在 `packages/presets/nocobase/src/server/index.ts` 和 `packages/core/server/src/plugin-manager/findPackageNames.ts`。

当前 `builtIn` 有 74 项。每一项都能在扫到的 `package.json` 里找到。`packages/plugins/@nocobase` 有 108 个社区包。不在 `builtIn` 里的社区包不会随预设默认装入。`packages/plugins/@nocobase-example` 有 21 个示例包。`packages/pro-plugins/@nocobase` 目录不存在，pro 包数量是 0。

包名包含 `market` 的数量是 0。文档里写了、源码树里没有的包，清单里目前只有 `@nocobase/plugin-workflow-approval`。

## 表单扩展点

这个提交同时包含两套客户端。

v1 客户端是 `@nocobase/client`。`SchemaInitializerManager.add` 注册初始化器，类定义在 `packages/core/client/src/application/schema-initializer/SchemaInitializerManager.ts`。表单块包括 `FormBlockInitializer`、`RecordFormBlockInitializer`、`FilterFormBlockInitializer`。`SchemaInitializerPlugin` 在 `packages/core/client/src/schema-initializer/index.ts` 里调用 `schemaInitializerManager.add`。

v2 客户端是 `@nocobase/client-v2`，引擎包是 `@nocobase/flow-engine`。`FlowEngine.registerModels` 在 `packages/core/flow-engine/src/flowEngine.ts`。表单块类是 `FormBlockModel`，文件是 `packages/core/client-v2/src/flow/models/blocks/form/FormBlockModel.tsx`。字段接口入口是 `CollectionFieldInterfaceManager.addFieldInterfaces`，文件是 `packages/core/client-v2/src/collection-field-interface/CollectionFieldInterfaceManager.ts`。

`@nocobase/flow-engine` 的 `description` 写的是 flow、model 和 action。审批与队列在 `@nocobase/plugin-workflow`。预设 `builtIn` 同时包含 `@nocobase/plugin-client` 和 `@nocobase/plugin-flow-engine`。根 `package.json` 的 `dev` 脚本是 `nocobase-v1 dev --rsbuild`。`dev:client-v2` 是另一条脚本。本文不指定市场后台必须用哪一套。

集合定义入口是 `@nocobase/database` 导出的 `defineCollection`。ACL 的范围集合是一个实例，文件是 `packages/plugins/@nocobase/plugin-acl/src/server/collections/rolesResourcesScopes.ts`，集合名是 `rolesResourcesScopes`。

`@nocobase/plugin-form-drafts` 版本 `2.1.37`，不在 `builtIn` 中，`editionLevel` 是 0。包描述是保存表单草稿并稍后继续编辑。发布资源的 revision CAS 不在这个插件里。

`@nocobase/plugin-multi-app-manager` 版本 `2.1.37`，源码在树里，不在 `builtIn` 中，`nocobase.deprecated` 为 true。包描述写明多应用以进程共享方式运行，只适合测试和演示，生产环境不要使用。不能把该插件当成市场的租户隔离。

## 审批与队列扩展点

`@nocobase/plugin-workflow` 版本 `2.1.37`，在 `builtIn` 中。服务端类是 `PluginWorkflowServer`，文件是 `packages/plugins/@nocobase/plugin-workflow/src/server/Plugin.ts`。扩展方法是 `registerTrigger` 和 `registerInstruction`。`initTriggers` 注册 `collection` 和 `schedule`。`initInstructions` 注册 `calculation`、`condition`、`multi-conditions`、`end`、`output`、`create`、`destroy`、`query`、`update`。

人工处理来自 `@nocobase/plugin-workflow-manual`，版本 `2.1.37`，在 `builtIn` 中。`load` 调用 `workflowPlugin.registerInstruction('manual', ManualInstruction)`，文件是 `packages/plugins/@nocobase/plugin-workflow-manual/src/server/Plugin.ts`。包描述是把部分决策交给用户。方案里绑定 `planHash` 的批准记录不在这个节点上。

`@nocobase/plugin-workflow-approval` 出现在文档 `docs/docs/en/plugins/@nocobase/plugin-workflow-approval/index.md`。该页 front matter 含 `isFree: false` 和 `editionLevel: 2`。源码树没有这个包。仓库内 `package.json` 的 `editionLevel` 只有 `0`，或没有该字段。没有大于 0 的值。

工作流执行进入队列的路径是 `Dispatcher.enqueue`。它调用 `this.plugin.app.eventQueue.publish`，文件是 `packages/plugins/@nocobase/plugin-workflow/src/server/Dispatcher.ts`。`PluginWorkflowServer.load` 用 `this.app.eventQueue.subscribe` 订阅 `channelPendingExecution`。常量 `WORKER_JOB_WORKFLOW_PROCESS` 的值是 `workflow:process`。

`EventQueue` 在构造时执行 `new MemoryEventQueueAdapter`。文件是 `packages/core/server/src/event-queue.ts`。该类是本文件里唯一的 `IEventQueueAdapter` 实现。`setAdapter` 允许换入别的 adapter。本仓库没有 Redis adapter，也没有 Bull adapter。

`@nocobase/plugin-async-task-manager` 版本 `2.1.37`，在 `builtIn` 中。`PluginAsyncTaskManagerServer.load` 把 `BaseTaskManager` 注册为容器中的 `AsyncTaskManager`，并调用 `registerTaskType(CommandTaskType)`。`BaseTaskManager` 订阅并发布的频道名是插件名加上 `.task`。文件是 `packages/plugins/@nocobase/plugin-async-task-manager/src/server/base-task-manager.ts`。包描述是管理导入、导出一类异步任务的进度和通知。

`PubSubManager` 在 `packages/core/server/src/pub-sub-manager/pub-sub-manager.ts`。它和 `EventQueue` 是两个类。

## 与拟议模块的差距

三个判定词的含义如下。

- Reuse 表示已有插件或类型承担该模块的职责。
- Partial 表示扩展点可调用，该模块自己的数据和动作不存在。
- Missing 表示对应该职责的扩展点不存在，或只有文档没有源码。

在 `packages/` 下检索 `market-catalog`、`publishers`、`resource_entries`、`installation_projection`，没有命中。

| 模块 | 判定 | 证据 |
| --- | --- | --- |
| market-catalog | Partial | `defineCollection`、v1 表单初始化器、v2 `FormBlockModel`、`ACL.registerSnippet` 和 `rolesResourcesScopes` 可以搭后台与数据范围。没有 publishers、resources、releases。 |
| market-publishing | Partial | `registerInstruction('manual')` 和 `@nocobase/plugin-form-drafts` 在树里。表单草稿不是发布 CAS。`@nocobase/plugin-workflow-approval` 无源码。没有扫描编排，也没有不可变 release。 |
| market-sources | Missing | 没有来源映射，也没有外部目录适配器。`AsyncTaskManager` 和 `@nocobase/plugin-file-manager` 是通用作业和文件能力。它们不是 Movo、WorkDSH、Tencent 或 OpenConnector 适配器。 |
| market-planning | Missing | 没有 plan、policy 或 entitlement 类型。人工节点不是 `planHash` 批准。 |
| market-observability | Partial | `@nocobase/plugin-audit-logs` 版本 `2.1.37` 在树里。预设 `deprecated` 包含它。包描述写明该插件已废弃，不要使用。工作流有 executions 与 jobs 集合。两者都不是按 consumerId 分区的安装投影。 |
