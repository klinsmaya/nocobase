# N05 依赖锁、企业策略、预检和分发资格

N05 仍在 `@nocobase/plugin-market-catalog`。租户列和草稿 CAS 的语义没有改。来源同步仍只拉元数据。

## 计划

`marketPlans:resolve` 写出一行期望计划。它固定已发布 release 的摘要，加上调用方提交的依赖锁，并抄下当前身份映射修订和当前生效策略。凭据只接受 `ref` 和 `purpose`。带有 token、password 或 secret 的请求返回 400，不插入计划。

`marketPlans:finalize` 合并目标消费端送来的预检。只有 `status=ready` 且 `source=live` 才把计划冻成 `frozen` 并写入 `planHash`。`blocked`、`choose`、`unreadable` 和 `stub` 都留下期望计划，不写哈希。预检记录追加写入，不改已冻结的哈希。

`planHash` 是规范化 JSON 的 `sha256:`。对象键排序。依赖、权限和凭据引用按稳定顺序去重。步骤顺序保留。同一次规范化得到同一个哈希。

## 批准

`marketPlans:approve` 只接受与冻结行完全相同的 `planHash`。审批人取认证用户。同一审批人再次提交同一个哈希返回原来的批准。另一位用户提交同一个哈希返回 409。

下面任一事实变化后，旧批准变成 `invalidated`，`marketPlans:eligibility` 返回 403。

- 身份映射修订
- 策略版本
- 权限摘要
- 预检摘要
- release 摘要
- release 被撤销
- 策略不再允许该消费方，或要求验证而映射未验证

`marketReleases:distribute` 对已撤销发布仍返回 403。资格检查同时看策略和映射，不把目录可见当成可分发。

## 不在这次里的东西
